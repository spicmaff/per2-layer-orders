# `MMMMVV` Explorer scene contract — integrated prepared batch

Generated site payload:

Python source:

## Fixed scientific scope

The contract uses canonical `MMMMVV` at `k=4` and contains exactly three prepared scenes:

1. **Diagonal success:** `(a,b)=(3,3)`.
2. **Boundary success:** `(a,b)=(1,4)`.
3. **Interior off-diagonal obstruction:** `(a,b)=(2,3)`.

The two compatible scenes contain exact Appendix-D construction orders generated by `per2.theory.constructions.mmmmvv_explicit_construction`. Each exported construction is independently checked once by the theorem-blind semantic validator before serialization.

The incompatible scene contains the directed four-cycle witness

`A4 ≺ A1 ≺ B1 ≺ B4 ≺ A4`

with edge origins, relation labels, deterministic reveal indices, and the cycle-closing edge preserved as exported theorem metadata.

## Browser integration

The existing coordinated Explorer consumes this record through prepared scene selection only. The browser does not determine whether a pair is diagonal, boundary or incompatible and does not build the witness. It renders exported status, rows, exact construction orders and witness edges.

Shareable examples:

- `explorer/?mechanism=mmmmvv&scene=diagonal`
- `explorer/?mechanism=mmmmvv&scene=boundary`
- `explorer/?mechanism=mmmmvv&scene=obstruction&step=4`

## Deliberate limitation

The UI remains fixed to the three approved scenes. The compatible construction records are combinatorial layer-order constructions, not physical folding trajectories. No event-by-event construction trace is claimed.
